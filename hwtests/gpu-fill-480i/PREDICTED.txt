gpu/gpu-fill-480i, before any console (2026-10-30).

psx-spx's dev text (cf1cd39, GPU misc, "Draw to display enable"): with E1h.10 clear in 480i a row whose parity equals GPUSTAT.31 at the moment it
is drawn is skipped, for polygons, lines, rectangles and GP0(02h), and a fill takes about half as long with the rows skipped. While bit 31 reads 1
only even rows are written, while it reads 0 only odd. The v0 GPU (an SCPH-1000) gets a fill's first row wrong: when it has the skipped parity it is
drawn and the row after it skipped instead, rows 0, 3, 5 ..., at widths 16 and 640, from lines 0 and 40, in either field; the v2 GPU does not. Whether
rectangles and polygons do the same on v0 is not known. Only inside the display area, NTSC.
